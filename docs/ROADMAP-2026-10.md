### この順番にした理由

- **小さく独立したもの（1〜3）を先に出す。** 早くリリースでき、失敗しても影響が小さい。
- **2（書き出し）を7（複数スクショ）より前に。** まとめて書き出すときに、2で作る共通の書き出し処理をそのまま使うため。
- **3（隠す）を4（軽量化）より前に。** 隠す表現は「形と方式だけ保存し、画像は開くたびに作る」設計にする。これは4の考え方と同じなので、先に小さく試せる。
- **4（軽量化）を6（フルページ）より前に。** 今の作りのまま縦長画像を扱うと、履歴と自動保存でメモリと保存容量が膨れ上がる（下の「現状の問題」参照）。
- **5（ファイル保存）を7より前に。** ファイル形式を最初から「複数プロジェクトを入れられる」形で決めておけば、7で形式を作り直さずに済む。
- **7は最後。** いちばん大きく、エディタ本体（`Editor.tsx`、現在2,176行）の分割を伴う。ほかの機能を入れ終えてから分割した方が、手戻りが少ない。

### 現状の問題（計画に影響するもの）

- **履歴と自動保存に背景画像が毎回入る。** `createSnapshot()` が `canvas.toObject()` をそのまま保存しており、背景画像（`FabricImage` の `src`＝画像データURL）が1回分ごとに丸ごと入る。履歴は最大30回分。通常のスクショでは目立たないが、フルページ画像（数MB〜数十MB）では破綻する。
- **v1.5の本物のぼかしが外された理由。** ぼかし画像を描画パターンとして持たせ、そのまま保存データに書き込んでいた。位置合わせのイベントも保存されないため、元に戻す・復元のあとでずれていた。v1.6.0で塗りつぶしに置き換えた際、ぼかし画像を作る処理（`blurCanvasRef`）だけが残り、今は使われていない。ガイドの文面も「ガウスぼかし」のまま。
- **拡張版には保存の仕組みがない。** 撮るたびに新しいタブでエディタが開き、閉じると消える。Web版は IndexedDB（Dexie）に最大15件を自動保存している。

## 3. 各ステップの詳細

### Step 1　楕円ツール

- **目的**：丸で囲む、という注釈の基本動作。今はスポットライト（円）と部分ズーム（楕円）しかない。
- **設計**
  - `src/editor/utils/drawTools/ellipse.ts` を新規作成（`rect.ts` と同じ作り。fabric の `Ellipse`。小さすぎる図形は描画を取り消す）
  - `useCanvasTools.ts`：`ToolType` に `'ellipse'` を追加し、押下・移動・離したときの処理をつなぐ
  - `Sidebar.tsx`：四角形のグループに追加。アイコンはスポットライト（円）と見分けがつくものにする
  - ショートカット `O`（現在は未使用）
  - `SubHeader.tsx`：四角形と同じ色・太さの操作を出す
  - 選択したとき色・太さがツールバーに反映されるよう、`Editor.tsx` の選択時の処理に追加
  - 文言：`public/_locales/{ja,en}/messages.json` に `toolEllipse`
  - ガイド：説明の節・章内チップ・ショートカット表に追加（GIFは撮影後に差し替え）
- **確認**：描く → 選択 → 色と太さの変更 → 元に戻す・やり直す → 保存して開き直す → 書き出し

### Step 2　書き出し形式の選択

- **目的**：PNG固定をやめる。チャットに貼る人向けに、軽いファイルを出せるようにする。
- **設計**
  - **先に共通化する**：`handleDownload` と `handleCopy` に同じ「等倍に戻して描画 → 画像化 → 表示を元に戻す」処理が重複している。これを `renderFullResolution({ format, quality, scale })` にまとめ、Blob を返す（`toDataURL` より `toBlob` の方が大きな画像でメモリに優しい）。Step 7 のまとめて書き出しもこれを使う
  - 保存ボタンの横に ▾ メニュー：形式（PNG／JPEG／WebP）、品質（JPEG・WebPのみ）、サイズ（等倍／50%／200%）
  - 前回の選択を localStorage に記憶（初期値は今と同じ PNG・等倍）
  - コピーは PNG のまま（クリップボードに確実に書けるのは PNG だけ）
  - JPEG は透明を扱えないので、フレームの角などの透明部分を白で埋める
  - ファイル名を `lumoshot_20261017-104512.png` のような日時形式にする
- **確認**：単体テスト（形式 → MIMEタイプ・拡張子の対応）。手動で各形式を書き出し、開けること・サイズが小さくなることを確認
- **実装メモ（2026-10-17 完了）**
  - 旧実装は表示中のキャンバスをそのまま画像化していたため、Retina（devicePixelRatio=2）では元画像の縦横2倍で書き出されていた。fabric の `toCanvasElement` を使い、高解像度用の倍率を切って描くことで「等倍＝元画像と同じ画素数」にした。表示中のキャンバスに触らないので、書き出し時のちらつきも無い
  - スポットライト・部分ズームの重ね描きは描画先（`after:render` の `ctx`）に描くよう変更。上側の層（選択枠）の描画では描かない
  - ⌘S（設定どおりに保存）と、何も選択していないときの ⌘C（画像をコピー）を追加。ガイドの表記に実装を合わせた
  - ラベル付きのヘッダーは画面幅約1260pxが必要だったため、文字ラベルを隠す幅を 960px → 1279px に変更

### Step 3　隠す表現の整理

- **目的**：「ぼかし」ツールを「塗りつぶし」ツールに改め、単色／モザイク／ぼかしから選べるようにする。ガイドの文面と実際の動きの食い違いも解消する。
- **設計**
  - ツール名を「塗りつぶし」にする（ショートカット `U` はそのまま）。サブツールバーで方式（単色／モザイク／ぼかし）を切り替え、強さ（モザイクの粗さ／ぼかしの強さ）をスライダーで調整。色は単色のときだけ。既定は単色
  - **保存するのは形と方式だけ**：`isBlur: true` に `redactMode`（`'fill' | 'mosaic' | 'blur'`）と `redactStrength` を追加。画像データは保存しない。`redactMode` が無い古いデータは単色として扱う（過去の保存データと互換）。内部名 `isBlur` / `blur-rect` は保存データ互換のため変えない
  - 新規 `src/editor/utils/redaction.ts`
    - 背景画像から、モザイク用（縮小してから補間なしで拡大）とぼかし用（`filter: blur()`）の元画像を作り、背景が変わるまで使い回す
    - 図形に描画パターンとして貼り、背景画像の位置に合わせて位置を補正する（フレーム表示・クロップ・リサイズ・Before/After の配置に対応）
    - 位置合わせを呼ぶタイミング：作成時、移動・拡大縮小時、保存データの読み込み後（`syncStateFromCanvas`）、クロップ・リサイズ・フレーム切り替え後（既存の `fire('moving')` 呼び出しが再び意味を持つ）
  - 保存データを作るときは描画パターンを外し、読み込んだあとで作り直す
  - Before/After で2枚目の画像の上に置いた場合に備え、元画像は「画像の層だけを合成したもの」から作る
  - 今は使われていない `blurCanvasRef` の処理は、この仕組みに置き換える
  - ガイドの「ガウスぼかし」の記述を直す
- **注意**：ぼかしは強くかけても、大きな文字なら読めたり復元を試みられたりする可能性がある。既定は塗りつぶしにし、ぼかしを選んだときに注意書きを出す
- **確認**：単体テスト（モザイク処理をピクセル配列で検証）。手動で3方式それぞれ、移動・元に戻す・保存して開き直す・フレーム切り替え・クロップ・書き出しを確認
- **実装メモ（2026-10-17 完了）**
  - `src/editor/utils/redaction.ts` に集約。モザイク・ぼかし画像は画像の層（背景・Before/After）から作り、層の状態が変わるまでキャッシュ。保存データには方式と強さだけを書き、パターンは `withoutRedactionPatterns` で外してから `toObject` する
  - パターンの位置合わせは「図形のローカル座標 → 幅・高さの半分ずらし → patternTransform」という fabric の描き方から逆算。書き出し画像で、モザイク範囲の全ブロックが元画像の12px平均と一致することを確認
  - 描き終わり・移動の終わりに位置を整数px・倍率1に正規化（端数があるとブロックの境がにじむ）
  - 複製・コピー＆貼り付けで塗りつぶしのプロパティを引き継ぐ
  - ぼかしは画像の端で透明を取り込むので、灰色を下敷きにして不透明にしてから貼る
  - **既存不具合の修正**：描画中の図形が 0.1 秒後の履歴記録で「描きかけ」のまま記録され、描き終わりは記録されていなかった（全ツール共通）。描いている間は object:added での記録を止め、描き終わりにキャンバスへ object:modified を通知して1回記録するようにした
  - クロップとリサイズは図形をずらす・拡大縮小するだけで作り直していなかったため、どちらも最後に正規化と作り直しを行うようにした（書き出し画像で全ブロック一致を確認）

### Step 4　保存データの軽量化

- **目的**：背景画像などの大きな画像を、履歴・自動保存に毎回書き込まないようにする。フルページと複数スクショの前提。
- **設計**
  - 保存データを作るとき、背景・Before/After の2枚目・挿入画像など大きな画像の `src` を `asset:<ハッシュ>` という参照に置き換え、画像本体は別の置き場（アセット）に1回だけ保存する
  - 履歴（メモリ上）：アセットはハッシュをキーに1回だけ保持
  - 自動保存（IndexedDB）：Dexie のバージョンを上げて `assets` テーブルを追加。プロジェクトを削除したら、どこからも使われていないアセットも消す
  - 読み込み時に参照を画像データに戻してから `loadFromJSON` する
  - 保存データに `formatVersion: 2` を付ける。旧形式（画像を直接含む）も読めるようにする
- **確認**：単体テスト（保存データの変換 → 復元で元に戻ること、旧形式が読めること）。手動で大きな画像を開いて30回ほど編集し、メモリ使用量が増え続けないことを確認

### Step 5　プロジェクトの保存と読み込み（`.lumoshot`）

- **目的**：編集途中の状態をファイルとして保存し、あとで再開する。別のPCへの移動やバックアップにも使える。自動保存がない拡張版では特に効く。
- **ファイル形式**（JSON）
  ```json
  {
    "app": "lumoshot",
    "formatVersion": 1,
    "name": "ログイン手順",
    "savedAt": 1792200000000,
    "projects": [{ "name": "ログイン手順", "state": "...", "thumbnail": "data:image/jpeg;base64,..." }],
    "assets": { "<ハッシュ>": "data:image/png;base64,..." }
  }
  ```
  1ファイルに複数のプロジェクトを入れられるよう、`projects` を配列にしておく（今は1件）。Step 7 で「選んだプロジェクトをまとめて1ファイルに保存」するときに形式を作り直さずに済む。
- **設計**
  - 書き出し：エディタのヘッダーのメニューに「ファイルに保存（.lumoshot）」（両方）
  - 読み込み（Web）：ホーム画面のアップロード・ドラッグ&ドロップで `.lumoshot` も受け付け、今は使われていない `createProjectFromFile()`（`projectStore.ts`）につなぐ
  - 読み込み（拡張）：ポップアップの「ファイルを開く」で `.lumoshot` も受け付け、`chrome.storage.local` 経由でエディタに渡す。`platform.extension.ts` が `restoreState` を扱えるようにする（型は既にある）
  - **外部から来るファイルなので検証を厳しくする**：形式とバージョンを確認する。画像は `data:image/...` だけを許可する（外部URLが入っていると、開いた瞬間に外部サーバーへ通信が発生し、「画像は端末内で完結」の約束が破れるため）。大きさの上限を設ける。問題があれば分かりやすいエラーを出す
- **確認**：単体テスト（壊れたファイル・未知のバージョン・外部URL入りを拒否すること、保存 → 読み込みで同じ状態に戻ること）

### Step 6　フルページスクリーンショット（拡張のみ）

- **目的**：縦に長いページ全体を1枚で撮る。手順書でよく要る。
- **設計**
  - ポップアップに「ページ全体（スクロール）」を追加
  - background からページにスクリプトを入れ、次を繰り返す：ページの高さを測る → 1画面分スクロール → 描画を待つ → `chrome.tabs.captureVisibleTab` で撮る
    - `captureVisibleTab` は1秒に2回までの制限があるので、間隔を0.5秒以上空ける
    - 2枚目以降は、固定表示（`position: fixed` / `sticky`）の要素を一時的に隠す（ヘッダーが何度も写り込むのを防ぐ）
    - 終わったらスクロール位置と隠した要素を元に戻す
    - 進み具合を表示する（撮影の瞬間だけ消す）
  - 撮った画像の帯は `chrome.storage.local` に置き（`unlimitedStorage` 権限は既にある）、エディタ側でつなぎ合わせる。最後の帯は重なった分を切り落とす
  - **大きさの上限**：Chrome の canvas は1辺32,767px・面積約2.7億pxが上限。超える場合は縮小するか、途中で切ってその旨を表示する
  - **対応しないページ**：ページ全体ではなく内側の枠がスクロールするアプリ（Gmail・Notion・Slack など）は v1 では対象外。ページがスクロールしないと分かったら、表示範囲の撮影に切り替えて知らせる。`chrome://` ページや Chrome ウェブストアは拡張がスクリプトを入れられないので、エラーを表示する
  - 必要な権限（`activeTab`・`scripting`・`storage`）は既にあるので、追加の権限は不要の見込み（実装時に確認）
  - **Web版**：実装しない。ホーム画面の撮影ボタンの近くに「ページ全体のスクロール撮影は Chrome 拡張機能版で使えます」という案内と、ストアへのリンクを置く
- **確認**
  - 単体テスト：スクロール位置の計画と、つなぎ合わせの位置計算（ページの高さ・画面の高さ・拡大率を入力にした純粋な関数として切り出す）
  - 手動：本物の `captureVisibleTab` は検証用の仕組みでは動かないため、**`dist/extension` を Chrome に読み込んで実機で確認が必要**。確認するページ：長い記事、固定ヘッダーのあるページ、画像を後から読み込むページ、内側の枠がスクロールするアプリ

### Step 7　複数スクショをまとめて扱う（1枚ずつ独立したプロジェクトを切り替える形）

一度に作らず、段階的に進める。保存の作り（1プロジェクト＝画像1枚）は今のまま流用する。

- **7a　下準備**
  - `src/web/projectStore.ts` を `src/lib/` に移し、拡張とWebで共有する（拡張のページでも IndexedDB は使える）
  - 拡張版にも自動保存と「最近の編集」を入れる（②）。撮影するたびに新しいプロジェクトとして保存され、タブを閉じても消えない
  - エディタ本体の部分的な分割：履歴（`useHistory`）、キャンバスの読み込みとリセット（`useCanvasDocument`）を切り出す。1つのエディタの中でプロジェクトを安全に切り替えるために必要
- **7b　切り替えパネル**：エディタの端に最近のプロジェクトのサムネイルを並べ、ホームに戻らずに切り替える。切り替える前に、編集中のプロジェクトを保存し切ってから次を開く（保存待ちの書き込みが次のプロジェクトを上書きしない）。拡張では、別のタブで撮ったばかりのプロジェクトもパネルに出る
- **7c　連番の続き**：連番ツールに「直前に編集したプロジェクトの続きから」のオプションを付ける（既定はオフ＝1から）
- **7d　まとめて書き出し**：パネルやホームで複数のプロジェクトを選び、Step 2 の書き出し処理で画像にして ZIP（軽量な `fflate` を想定）で保存。ファイル名はプロジェクト名から作る（重複は連番を付ける）。スポットライトなどの重ね描きは描画のたびのイベントで描いているので、開いていないプロジェクトを書き出すために、その処理を画面外のキャンバスにも付けられるよう切り出す。選んだプロジェクトをまとめて1つの `.lumoshot` に保存することもできる
- **確認**：単体テスト（連番の続き番号の計算、ZIP内のファイル名の重複処理）。手動で切り替え・保存の取りこぼしがないこと・まとめて書き出し

## 4. 毎ステップ共通の確認とリリース

1. 型チェック・単体テスト（Vitest）・拡張とWebの両方のビルド

## 5. リスク

| リスク | 対策 |
|---|---|
| フルページで巨大な画像になり、メモリ不足やタブの強制終了が起きる | Step 4 を先に行う。大きさの上限を設けて縮小・切り詰め |
| フルページで固定ヘッダーの重複、後から読み込む画像の写り漏れ | 固定要素を隠す。スクロールごとに描画を待つ。完全には防げないサイトがあることをガイドに書く |
| 撮影中に background の service worker が止まる | 撮影ループをメッセージのやり取りで進め、長い待機を作らない |
| ぼかしの判読・復元 | 既定は塗りつぶし。ぼかしに注意書き |
| `.lumoshot` に外部URLや壊れたデータが入っている | 読み込み時に `data:image/` 以外を拒否し、形式を検証する |
| `Editor.tsx` がさらに肥大化する | 各ステップで関係する処理を切り出す（Step 2 で書き出し、Step 3 で隠す表現、Step 7a で履歴・読み込み） |

- OCR・クラウド同期・アカウント・操作の自動記録・広告（2026-07 の方針で見送り済み）
